# Development

```zsh
git clone https://github.com/rahimnathwani/mailbox-viewer && cd mailbox-viewer
make install     # uv sync, npm ci for the viewer, Playwright's Chromium
make test        # pytest + browser tests
make lint        # ruff + Biome + TypeScript
make dev         # viewer with hot reload at http://localhost:5173, data from ./dist
```

`make help` lists every target.

## Layout

| Path | Contents |
|---|---|
| `src/mailbox_viewer/` | Python package: `cli`, `ingest` (inputs, readpst), `parse`, `threads`, `attachments`, `textutil`, `build`, `publish`, `serve` |
| `src/mailbox_viewer/embed/` | Node script that embeds text with transformers.js (installed into the cache on first use) |
| `src/mailbox_viewer/search-config.json` | Tokenizer, BM25 and embedding settings shared by build and viewer |
| `viewer/` | React app: `src/lib/` (DuckDB, search engine, router, local state), `src/components/`, `tests/` (Playwright) |
| `tests/` | pytest suite; `fixtures/demo/` is a fictional mailbox, regenerated by `fixtures/make_demo.py` |
| `docs/` | This documentation; `cli.md` is generated |

## Ground rules

- **Fictional data only** in tests, fixtures, screenshots and docs. Real mailboxes stay in `input/` and `dist/`, which git ignores. When a bug shows up in real mail, reproduce it with invented names.
- **Tokenizer parity**: `viewer/src/lib/search/tokenize.js` must produce exactly the tokens `textutil.tokenize` does; `tests/test_tokenizer_parity.py` runs both. Bump `tokenizer.version` in `search-config.json` when either changes.
- **Format changes** that break readers bump `FORMAT_VERSION` and are described in [format.md](format.md). Adding a column isn't a break: the viewer treats newer columns as optional.
- **Range requests**: `viewer/tests/viewer.spec.ts` fails if any Parquet file is downloaded whole. Keep it passing.

## Tests

| Suite | Command | Covers |
|---|---|---|
| **pytest** | `uv run pytest` | Parsing edge cases, threading, ingest layouts, index layout, serving headers, tokenizer parity |
| **Playwright** | `npm --prefix viewer run test:e2e` | Builds the demo mailbox and drives the viewer: search operators, threads, previews, keyboard, mobile |
| **Docs** | `make docs-check` | `docs/cli.md` matches `mbv --help` |

## Generated docs

`docs/cli.md` is rendered from the CLI's help with [cog](https://cog.readthedocs.io):

```zsh
make docs        # rewrite docs/cli.md
```

## Releasing

1. Update `__version__` in `src/mailbox_viewer/__init__.py`, the viewer's `package.json`, and `CHANGELOG.md`.
2. Commit, tag `vX.Y.Z`, push the tag.
3. The [release workflow](../.github/workflows/release.yml) builds the viewer, the wheel and sdist, creates the GitHub release, publishes the Docker image to `ghcr.io/rahimnathwani/mailbox-viewer`, and publishes to PyPI once a [trusted publisher](https://docs.pypi.org/trusted-publishers/) is configured for the repository (set the repository variable `PUBLISH_TO_PYPI` to `true`).
